# Finance Organizer

Управленческий учет двух компаний: брокера и поставщика ликвидности. Стек: ASP.NET Core 8 Razor Pages, CQRS, EF Core, PostgreSQL.

## Запуск

```powershell
docker compose up --build
```

Открыть http://localhost:5050. Пароль БД для production задается переменной `POSTGRES_PASSWORD`.

## Миграции

### Переводы между своими счетами

В разделе «Операции» есть кнопка создания перевода и фильтр «Перевод между своими
счетами». В карточке доступны редактирование и отмена. Сумма, оба счёта, дата и
комментарий изменяются вместе; предыдущие версии и авторы сохраняются в истории.
Отмена исключает обе стороны из расчёта остатков, сохраняя запись в операциях и
историю. Повторная отмена не создаёт новых движений. Проверяется версия перевода,
чтобы параллельные изменения не перезаписывали друг друга.

Перевод имеет запись для общего списка и отдельную пару `AccountMovements` для
остатков. Он не создаёт `Settlements` сделки и исключён из торговых оборотов,
дохода, расходов и прибыли. Переводы из модального окна «Баланс» используют ту же
логику. Права создания, просмотра и редактирования карточек соответствуют правам
раздела «Операции»; старое окно создания сохраняет права раздела «Баланс».

Миграция `AddEditableOwnTransfers` добавляет признаки отмены, версии и журнал
изменений, а также создаёт записи общего списка для существующих корректных пар
переводов. Она не создаёт новых движений и не меняет остатки. Для старых переводов
автор помечен неизвестным. После применения миграции старые переводы открываются
и редактируются наравне с новыми. Миграция применяется при старте приложения.

```powershell
dotnet run --project tests/TransferRegression/TransferRegression.csproj
```

### Импорт листа «Август 2026» A&A Liquidity

Подготовленный файл `imports/august-2026.json` содержит только август: 385 операций,
755 фактических движений, исходные строки, месячные расходы и контрольные остатки.
В строках 328, 330, 332, 334 дата взята из предыдущей строки (25.08.2026).
Односторонние строки сохранены с нулевой встречной суммой: фиктивные поступления
или списания не создаются. Банки привязаны к фактической стороне движения.

Для подготовки файла из исходного Excel (Python с `openpyxl`):

```powershell
python .import-tools/prepare_liquidity_month.py "Ликвидность A&A 2026 (1).xlsx" imports/august-2026.json --sheet "Август 2026"
```

Docker Compose передаёт `LiquidityMonthImportPath=/app/import/august-2026.json`.
При запуске импорт выполняется одной транзакцией в существующей PostgreSQL,
после миграций схемы и основного исторического импорта. Файл должен находиться
в смонтированной папке `imports`. Приложение без этого файла запускается без
дополнительного импорта. Путь можно переопределить переменной
`LIQUIDITY_MONTH_IMPORT_PATH` в Compose или `LiquidityMonthImportPath` в конфигурации.

Повторный запуск не добавляет дубликаты платежей. Месячные контрольные таблицы
обновляются из Excel, сохраняя идентификаторы. Отменённые операции и операции с
уже существующими платежами сохраняются. Если операция без платежей изменена
вручную, импорт останавливается для сверки, а транзакция откатывается.
Начальные остатки отдельных банков не перезаписываются: Excel содержит начальные
остатки только по валютам. Месячный отчёт использует эти контрольные остатки;
балансы отдельных счетов рассчитываются из их начальных остатков и платежей.
Банковские комиссии из строк не списываются повторно поверх месячных расходов.

Проверка импорта на отдельной тестовой базе в памяти:

```powershell
dotnet run --project tests/LiquidityImportRegression/LiquidityImportRegression.csproj -- imports/august-2026.json
```

Контроль августа: расходы 151 460,7926 и чистая прибыль 412 133,1297 в
эквиваленте USDT. Конечные остатки: USDT 3 111 492,132; USD 5 039 117,047;
RUB 1 301 663,651; AED 30 024 784,43. Разница сверки по валютам меньше 0,01.

При старте приложение применяет ожидающие EF Core migrations через `Database.MigrateAsync()`. Начальная миграция лежит в `organaizer/Infrastructure/Migrations`.

```powershell
dotnet tool restore
dotnet tool run dotnet-ef migrations add MigrationName --project organaizer/organaizer.csproj --startup-project organaizer/organaizer.csproj --output-dir Infrastructure/Migrations
dotnet tool run dotnet-ef database update --project organaizer/organaizer.csproj --startup-project organaizer/organaizer.csproj
```

Интерфейс основан на бесплатном MIT-licensed Tabler, версия зафиксирована на 1.4.0.

- Пароль: `inFO@)20`

Супер-администратор создаётся автоматически:

- Логин: `superadmin`
- Пароль: `12345678`

Раздел «Пользователи и права» позволяет выдавать отдельные разрешения на просмотр, создание и редактирование. Право «Диаграммы и итоги» используется также приложением аналитики на порту `5045`; вход выполняется теми же учётными записями.

Пользователь и роль `Administrator` создаются идемпотентно при первом старте. Для production тестовый пароль необходимо заменить.

## Справочники и отчетность

- Справочник валют: AED, CNY, EUR, KGS, RUB, USD, USDT; валюты выбираются из выпадающих списков.
- Справочник клиентов заполняется идемпотентно из исходных таблиц Orient Capital и A&A и поддерживает ручное добавление/редактирование.
- Промежуточный месячный отчет показывает итоги по типам операций, валютные потоки, расходы и график прибыли.
- Seed добавляет только отсутствующие записи. При обновлении `docker compose up -d --build` существующий PostgreSQL volume не очищается.
- Исторический импорт из Excel хранит ключ источника, лист, номер строки и исходный JSON. Повторный запуск безопасен и не создает дубликаты.

Сделка хранит две валютные стороны, комиссию, прибыль в базовой валюте и срок расчета. Фактические движения (`Settlement`) могут поступать частями и в разные дни; знак суммы означает приход или расход по счету. Остаток счета равен начальному остатку плюс все движения. Статус сделки закрывается после покрытия обеих сторон.

CQRS реализован отдельными командами и запросами в `Application/Cqrs.cs`; запись и чтение не смешиваются в PageModel.
